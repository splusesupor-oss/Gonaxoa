# ربات پیام ناشناس سروش‌پلاس

ربات سبک Python برای دریافت پیام خصوصی کاربران و انتقال آن به مالک، با امکان پاسخ مالک از طریق Reply. ارتباط با **Bot API واقعی سروش‌پلاس** از طریق HTTPS و HTTPX انجام می‌شود؛ این پروژه از Telegram API یا کتابخانه‌های تلگرام استفاده نمی‌کند.

## قابلیت‌ها

- `/start` و کیبورد پاسخ دائمی با یک دکمه «✉️ پیام ناشناس به مالک»
- دریافت متن و انواع پیام پشتیبانی‌شده توسط API؛ محتوا با `copyMessage` کپی می‌شود تا فوروارد، انتساب فرستنده به پیام اضافه نکند.
- ارسال نام نمایشی، یوزرنیم در صورت وجود، شناسه عددی و نوع پیام در پیام جداگانه‌ای که فقط مالک می‌بیند.
- ذخیره رابطه میان پیام‌های ربات در گفت‌وگوی مالک و کاربر اصلی در SQLite؛ پاسخ مالک باید روی پیام مشخصات یا پیام محتوای کپی‌شده Reply شود.
- تشخیص Reply نامعتبر و محدودکردن پاسخ‌گویی به شناسه عددی مالک.
- اگر `OWNER_ID` خالی باشد، برنامه اجرا می‌شود ولی ارسال ناشناس غیرفعال است.
- مدیریت خطاهای API/شبکه، تکرار polling با تأخیر افزایشی و نگهداری cursor دریافت به‌روزرسانی‌ها در SQLite.

## نصب و اجرا در Termux

۱. Python و Git را نصب کنید:

```sh
pkg update -y && pkg install python git -y
```

۲. وارد پوشه پروژه شوید و محیط مجازی بسازید:

```sh
cd soroush_anonymous_bot
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

۳. فایل تنظیمات خصوصی را ایجاد کنید و ویرایشش کنید:

```sh
cp .env.example .env
nano .env
```

- `SPLUS_BOT_TOKEN`: توکن جدید BotFather سروش‌پلاس.
- `OWNER_ID`: شناسه **عددی** مالک. تا وقتی خالی است، قابلیت ارسال برای مالک خاموش می‌ماند.
- `OWNER_USERNAME`: اختیاری و فقط برای یادداشت؛ نام کاربری به‌تنهایی برای احراز هویت به کار نمی‌رود.

۴. اجرا:

```sh
python bot.py
```

برای توقف `Ctrl+C` را بزنید. فایل `bot.sqlite3` خودکار ساخته می‌شود و نباید حذف شود؛ نگاشت پیام‌ها برای پاسخ بعد از راه‌اندازی مجدد در آن نگهداری می‌شود.

## تنظیم شناسه مالک

در ابتدا می‌توانید `OWNER_ID=` را خالی بگذارید. برای دریافت شناسه عددی، با ربات خود گفت‌وگوی خصوصی آغاز کنید و از ابزار/ربات مورد اعتماد نمایش شناسه استفاده کنید یا یک‌بار موقتاً اطلاعات `from.id` پیام خود را در لاگ خصوصی برنامه ثبت کنید. شناسه را در خط `OWNER_ID=...` قرار دهید و ربات را دوباره اجرا کنید. نام کاربری ممکن است تغییر کند؛ شناسه عددی معیار دسترسی است.

## محدودیت‌های API

- مستندات رسمی `copyMessage` را برای کپی انواع پیام مستند کرده‌اند؛ پیام‌های سرویس و محتوای محافظت‌شده قابل کپی نیستند. در چنین حالتی، ربات برای مالک یک پیام جایگزین قابل Reply می‌سازد و به کاربر محدودیت را اعلام می‌کند.
- اگر نسخه یا کلاینت سروش‌پلاس در ارسال/کپی یک نوع پیام پاسخ ندهد، ارسال پاسخ خطا می‌گیرد؛ پاسخ متنی در صورت امکان به‌عنوان fallback ارسال می‌شود.
- به‌روزرسانی‌های دریافتی API بیش از ۲۴ ساعت نگهداری نمی‌شوند. ارتباط Reply پس از دریافت در SQLite پایدار است.
- API مستندات، `getUpdates` و Webhook را دو روش جدا می‌داند. این نسخه برای Termux از long polling استفاده می‌کند و وب‌سرور یا پورت ورودی نمی‌خواهد.
- اگر ربات هم‌زمان در جای دیگری polling می‌شود، تنها یک نمونه را اجرا کنید؛ دو poller می‌توانند در دریافت به‌روزرسانی‌ها تداخل کنند.

## امنیت

- هیچ توکنی را در فایل‌های کد یا Git commit نکنید. `.env` در `.gitignore` است.
- شناسه کاربر و mapping پیام‌ها در `bot.sqlite3` ذخیره می‌شود؛ فایل دیتابیس را خصوصی نگه دارید.
- پاسخ‌گویی فقط بر اساس تطابق شناسه عددی کاربر و شناسه گفت‌وگوی خصوصی مالک انجام می‌شود؛ `OWNER_USERNAME` صرفاً کمکی است.
