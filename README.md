# ربات پیام ناشناس سروش‌پلاس

ربات سبک Python برای دریافت پیام خصوصی کاربران، ارسال پیام ناشناس به مالک و پاسخ مالک از طریق Reply. ارتباط با Bot API رسمی سروش‌پلاس از طریق HTTPS و HTTPX است؛ از Telegram API یا کتابخانه‌های مخصوص تلگرام استفاده نمی‌شود.

## قابلیت‌ها

- `/start` و منوی Reply Keyboard دائمی با دکمه‌های «🚀 استارت»، «✉️ پیام ناشناس به مالک» و «📖 راهنمای استفاده».
- دکمه‌های منو با فیلد مستندشدهٔ `KeyboardButton.style` و مقدار آبی `primary` ارسال می‌شوند؛ کیبورد یک‌بارمصرف نیست و در پاسخ‌های عادی کاربر دوباره ضمیمه می‌شود.
- دریافت متن و انواع پیام پشتیبانی‌شده توسط API با `copyMessage`، بدون افزودن انتساب فوروارد.
- نمایش نام نمایشی، یوزرنیم (در صورت وجود)، شناسه عددی و نوع پیام فقط در پیام خصوصی مالک.
- نگهداری نگاشت پاسخ در SQLite و محدودکردن پاسخ مالک به شناسه عددی تنظیم‌شده.
- ثبت لاگ شناسایی با قالب `OWNER_DISCOVERY | chat_id=... | user_id=... | username=...`؛ متن پیام، نام نمایشی و توکن در این لاگ نوشته نمی‌شوند.
- اگر `OWNER_ID` تنظیم نشده باشد، ربات اجرا می‌شود اما ارسال به مالک و مسیرهای ویژه مالک فعال نیستند؛ هیچ کاربری خودکار مالک نمی‌شود.
- مسدود کردن کاربر توسط مالک با یوزرنیم یا چت‌ایدی عددی؛ کاربر مسدود دیگر نمی‌تواند پیام ناشناس بفرستد (جزئیات پایین‌تر).

## مسدود کردن کاربر

فقط مالک (همان `OWNER_ID` در گفت‌وگوی خصوصی) می‌تواند از دستورهای زیر استفاده کند. بقیهٔ کاربران با فرستادن همین متن‌ها هیچ کاری نمی‌کنند.

| دستور | کارکرد |
| --- | --- |
| `مسدود @osinw` | مسدود کردن با یوزرنیم |
| `مسدود 123456789` | مسدود کردن با چت‌ایدی عددی |
| `مسدود` (به‌تنهایی، در Reply روی پیام کاربر) | مسدود کردن فرستندهٔ همان پیام |
| `رفع‌مسدود @osinw` یا `رفع‌مسدود 123456789` | برداشتن مسدودیت |
| `لیست‌مسدود` | نمایش فهرست مسدودها |

نکته‌ها:

- یوزرنیم را با یا بدون `@` می‌توانید بنویسید؛ حروف بزرگ و کوچک، فاصله و نیم‌فاصله تفاوتی ایجاد نمی‌کند (`مسدود@osinw` هم پذیرفته می‌شود). معادل‌های انگلیسی `block` / `unblock` / `blocklist` هم کار می‌کنند.
- اگر کاربر قبلاً با ربات صحبت کرده باشد، یوزرنیم فوراً به شناسهٔ عددی او تبدیل می‌شود؛ بنابراین تغییر یوزرنیم بعدی راه فراری از مسدودیت نیست. اگر کاربر هرگز با ربات صحبت نکرده باشد، یک قاعدهٔ یوزرنیمی ثبت می‌شود و به‌محض اولین پیام او، مسدودیت قطعی و مبتنی بر شناسهٔ عددی می‌شود.
- کاربر مسدود هنگام زدن دکمهٔ ارسال یا فرستادن محتوا پیام «⛔️ امکان ارسال پیام ناشناس برای شما در حال حاضر وجود ندارد.» را می‌گیرد و پیامش هرگز به مالک نمی‌رسد. اگر در همان لحظه در حال نوشتن پیام بوده، وضعیت انتظارش پاک می‌شود.
- مسدود شدن روی `copyMessage` و ارسال واقعی اثر می‌گذارد؛ نه فقط روی نمایش. کاربر مسدود همچنان می‌تواند `/start` و راهنما را ببیند.
- مسدود کردن خودِ مالک مجاز نیست. شناسه‌های منفی (گروه/کانال) به‌عنوان چت‌ایدی کاربر پذیرفته نمی‌شوند.
- فهرست مسدودها در جدول `blocked_users` همان `bot.sqlite3` ذخیره می‌شود و بعد از ری‌استارت باقی می‌ماند.

## نصب و اجرا در Termux

۱. Python و Git را نصب کنید:

```sh
pkg update -y && pkg install python git -y
```

۲. وارد پوشه پروژه و محیط مجازی شوید:

```sh
cd Gonaxoa
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

۳. تنظیمات خصوصی را بسازید:

```sh
cp .env.example .env
nano .env
```

- `SPLUS_BOT_TOKEN`: توکن BotFather سروش‌پلاس را فقط اینجا وارد کنید.
- `OWNER_ID`: فعلاً خالی بماند تا مالک از لاگ شناسه را پیدا کند؛ سپس آن را تنظیم کنید.
- `OWNER_USERNAME`: اختیاری و فقط برای یادداشت است و برای احراز هویت استفاده نمی‌شود.

۴. اجرا:

```sh
python bot.py
```

برای توقف `Ctrl+C` را بزنید. `bot.sqlite3` به‌طور خودکار ساخته می‌شود؛ آن را حذف نکنید، چون نگاشت Reply در آن ذخیره است.

## پیدا کردن و تنظیم OWNER_ID

۱. `OWNER_ID=` را خالی بگذارید، برنامه را اجرا کنید و مالک از گفت‌وگوی خصوصی خودش با ربات `/start` بفرستد.
۲. در لاگ برنامه خطی مانند این پیدا کنید:

```text
OWNER_DISCOVERY | chat_id=123456789 | user_id=123456789 | username=example
```

۳. مقدار `chat_id` را در `.env` قرار دهید:

```dotenv
OWNER_ID=123456789
```

۴. ربات را متوقف و دوباره اجرا کنید. در گفت‌وگوی خصوصی، `chat_id` معمولاً با `user_id` برابر است؛ مقدار مورد استفاده برای `OWNER_ID` همان `chat_id` ثبت‌شده است. اگر username خالی باشد، `username=unknown` ثبت می‌شود. نام یا username به‌تنهایی هرگز مالک را تعیین نمی‌کند.

## محدودیت‌های API

- `copyMessage` انواع پیام پشتیبانی‌شده را کپی می‌کند؛ پیام‌های سرویس یا محتوای محافظت‌شده ممکن است قابل کپی نباشند. در این حالت، ربات به کاربر و مالک اطلاع می‌دهد و برای مالک یک پیام جایگزین قابل Reply می‌سازد.
- API دریافت‌های `getUpdates` و Webhook را جدا می‌داند. این نسخه برای Termux از long polling استفاده می‌کند و به دامنه یا پورت ورودی نیاز ندارد.
- `copyMessage` و بقیهٔ متدهای استفاده‌شده در این پروژه، متد مسدودسازی سمت سرور (`blockChat` یا مشابه) نیستند؛ مسدودسازی کامل در سطح خود ربات و در پایگاه‌داده انجام می‌شود و به متد اضافی از API نیاز ندارد.
- فقط یک نمونه ربات را هم‌زمان اجرا کنید تا pollerها در دریافت پیام‌ها تداخل نکنند.

## امنیت

- توکن در کد یا مخزن نیست؛ `.env` در `.gitignore` قرار دارد و `.env.example` فقط مقدار نمونه دارد.
- اطلاعات لاگ discovery به شناسه‌های عددی و username عمومی محدود است؛ متن پیام و اطلاعات محرمانه لاگ نمی‌شود.
- نگاشت کاربر/پیام در `bot.sqlite3` نگهداری می‌شود؛ این فایل را خصوصی نگه دارید.
- برای اجرای دستور `مسدود @username`، ربات جفت یوزرنیم↔شناسهٔ عددی کاربرانی را که به آن پیام داده‌اند در جدول `known_users` نگه می‌دارد. این جدول شامل متن پیام‌ها نیست و فقط برای تبدیل یوزرنیم به شناسه و پایدار ماندن مسدودیت استفاده می‌شود.
